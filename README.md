# TMTF 검사 — 인공와우 사용자용

‘쉬—’ 하는 소리 세 개 중 **떨리는 소리 하나**를 찾는 듣기 검사입니다.
얼마나 약한 떨림까지 구별할 수 있는지를 떨림 속도(10–200 Hz)마다 측정합니다.
연구에서는 이를 시간 변조 탐지, TMTF(temporal modulation transfer function)라고 합니다.

## 바로 해보기

**https://mi-rae-lab.github.io/ci-tmtf-test/**

별도 설치 없이 위 주소를 크롬·엣지·사파리에서 열면 바로 사용할 수 있습니다.

## 이 검사를 하면 알 수 있는 것

- **미세한 소리 떨림 감지 수준**: 느린 떨림부터 빠른 떨림까지 얼마나 약한 떨림을 구별할 수 있는지 그래프로 확인할 수 있습니다.
- **말소리 리듬·변화 파악 참고**: 말소리는 크기가 빠르게 변하며 이어집니다. 내 귀와 음성처리기(인공와우 외부기기)가 이런 빠른 소리 변화를 얼마나 잘 따라가는지 참고할 수 있습니다.
- **양쪽 귀 및 설정 전후 비교**: 왼쪽·오른쪽 귀를 따로 해보거나, 음성처리기 설정·프로그램을 바꾸기 전과 후를 같은 조건으로 비교해 볼 수 있습니다.
- **상담용 보고서 저장**: 검사가 끝나면 **전문가용 보고서(`.html`)**로 저장해 청능사나 인공와우 엔지니어와 상담할 때 참고 자료로 활용할 수 있습니다.

## 준비할 것

- 조용한 장소
- 약 20분 (중간에 쉴 수 있습니다)
- 평소 사용하는 음성처리기 프로그램과 볼륨
- 컴퓨터 사용을 권장합니다 (휴대폰·태블릿도 가능)
  - 아이폰은 측면 무음 스위치를 해제해야 소리가 납니다.

## 진행 순서

1. **시작하기**를 누르고 검사할 귀와 소리 듣는 방법을 선택합니다.
   - 한쪽 귀만 검사할 때는 반대쪽 음성처리기(인공와우 외부기기)나 보청기를 잠시 빼 주세요.
2. **소리 재생**을 누르고 기기 볼륨을 편안하게 잘 들리는 크기로 맞춥니다.
   - 소리 앞부분이 잘리는 것을 막기 위해 소리가 재생될 때 거의 들리지 않는 아주 낮은 유지 신호가 자동으로 켜집니다(원하면 끌 수 있습니다).
   - 볼륨을 맞춘 뒤에는 검사가 끝날 때까지 바꾸지 말아 주세요.
3. **짧은 소리 점검**을 2번 진행합니다(각 3초 대기 후 짧은 소리 4개). 앞부분이 잘리는지 확인하며, 원하면 건너뛸 수 있습니다.
4. **연습**을 3번 진행합니다. 연습 결과는 최종 기록에 포함되지 않습니다.
5. **본 검사**를 진행합니다. 소리가 날 때 1 · 2 · 3번 칸에 차례로 불이 켜집니다.
   - 떨리는 소리의 번호를 선택해 주세요. 키보드 1 · 2 · 3도 사용할 수 있습니다.
   - 떨림이 아주 조금이라도 느껴지면 그 번호를 선택해 주세요. 세 소리가 완전히 똑같이 들릴 때만 **모르겠음**(키보드 0)을 눌러 주세요.
   - 처음에는 쉽지만, 맞힐수록 떨림이 미세해져 점점 어려워집니다.
6. 검사가 끝나면 **결과 파일 저장**을 눌러 저장하고, 필요하면 청능사나 연구자에게 전달합니다.
   - 청능사나 인공와우 엔지니어와 상담할 때는 **전문가용 보고서 저장**(`.html`, 브라우저에서 열어 인쇄·PDF 저장 가능, 참고용)을 함께 활용하실 수 있습니다.
   - 시간이 되시면 **한 번 더 하기**를 진행해 주세요. 두 번 측정하면 결과가 더 정확해집니다.

## 검사를 보내는 분께

- **링크로 번호 붙이기 (`#` 해시 권장 — 서버 미전송):** 주소 뒤에 `#id=P02`를 붙여 보내면 번호 칸이 채워지며, `#` 뒤 내용은 서버로 전송되지 않습니다(기존 `?id=P02`도 하위 호환).
  - 예: `https://mi-rae-lab.github.io/ci-tmtf-test/#id=P02`
- **떨림 속도 바꾸기:** `#hz=10,50,100`처럼 적으면 그 값들로 검사합니다.
  - 기본값은 10 · 50 · 100 · 150 · 200 Hz입니다.
  - 고를 수 있는 값은 5–300 Hz의 5 Hz 간격, 55–70 Hz의 1 Hz 간격, 2 · 4 · 8 · 16 · 32 · 64 · 128 · 256 · 512 Hz입니다.
  - 하나라도 틀린 값이 있으면 기본값으로 합니다. 최대 12개입니다.
  - 둘 다 쓰려면 `#id=P02&hz=10,50,100`처럼 `&`로 잇습니다.
- **영어 화면 링크:** 주소 뒤에 `#lang=en`을 붙이거나 화면 오른쪽 위의 `EN` / `KO` 단추로 전환할 수 있습니다.
  - 예: `https://mi-rae-lab.github.io/ci-tmtf-test/#id=P02&lang=en`
- **결과 파일 열기:** 첫 화면 맨 아래 **결과 파일 열기 (청능사·연구자용)**에서 파일을 고르면 다음을 봅니다(`formatVersion: 1`과 `2` 모두 지원).
  - 표와 그림, 측정마다의 계단 그림, 유지 신호 방식 및 짧은 소리 점검(온셋) 결과
  - 같은 참가 번호 회기가 둘 이상이면 표와 겹친 그래프로 자동 비교 (단, 유지 신호 방식이 다른 회기는 합치지 않고 분리)
  - 계단 다시 돌리기, 구간 세기, 정답 자리별 맞힘(모르겠음 제외) 점검
  - 전문가용 보고서(`.html`), 측정 CSV, 시행 CSV로 저장할 수도 있습니다.
  - 파일은 그 화면 안에서만 읽습니다.
- **결과 파일 따로 점검하기:** 앱 코드를 쓰지 않고 따로 짠 파이썬으로 계단과 소리를 다시 만들어 봅니다(numpy 필요).

  ```
  python -I -X utf8 tools/verify_result.py 받은파일.json
  ```
- **연구에 쓰려면** 기관 생명윤리위원회(IRB) 심의와 참가자 동의가 먼저 필요합니다.

## 검사 방법 (요약)

자세한 내용은 [방법.md](방법.md)에 있습니다.

| | |
|---|---|
| 과제 | 3구간 중 다른 하나 고르기 (0.5초 소리 × 3, 사이 0.5초) |
| 소리 | 광대역 가우스 잡음, 정현 진폭 변조. 변조 시작 위상은 구간마다 무작위. 세 소리의 평균 세기(RMS)는 정확히 같게 맞춤 |
| 켜짐·꺼짐 | 10 ms 직선 경사, 첫 소리 앞 무음 0.25초 |
| 계단 | 2-down 1-up(70.7% 지점). 변조 100%(0 dB)에서 시작해 반전 4번까지 4 dB, 그 뒤 2 dB. 반전 14번 중 마지막 10번 평균 |
| 끝 규칙 | 0 dB에서 4번 틀리면 ‘재지 못함’으로 멈춤 (앱 자체 안전 규칙 · 평균 제외) |
| 반복 | 한 바퀴(주파수마다 1번), 원하면 한 바퀴 더. 두 값이 3 dB 넘게 다르면 그것만 한 번 더 (Won 등 2011 · Park 등 2015) |
| 피드백 | 답할 때마다 맞음 · 틀림을 보여 줌 |

## 검증

자극과 계단 코드(`js/stim.js` · `js/track.js` · `js/protocols.js`)는 다음 세 가지로 확인했습니다. 화면 흐름은 가짜 화면으로 처음부터 끝까지 돌려 봤습니다.

- 따로 짠 파이썬과 대조
- Lean 4 형식 증명
- JS ↔ Lean 줄 단위 대조

```
tools\전수검산.bat        (또는 python -I -X utf8 tools/run_checks.py)
```

- 필요: Python 3 + numpy, [deno](https://deno.com), Lean 4(elan)
- 6단계가 모두 통과하면 `검증_통과.json`에 기록이 남습니다.
- 검사 화면은 회기를 시작할 때 자기 파일의 해시를 이 기록과 맞대어 회기에 적습니다.
- 새 판이 나왔을 때만 새로 고침을 안내합니다. 해시만 다르면 막지 않고 기록에 남깁니다.

| 파일 | 내용 |
|---|---|
| `index.html` · `style.css` · `js/app.js` | 참가자 화면, 기록, 검사 흐름, 결과, 받은 결과 보기 |
| `js/protocols.js` · `js/stim.js` · `js/track.js` | 절차, 자극(씨앗으로 되풀이되는 잡음), 적응 계단 |
| `tools/` | 전수 검산 (`run_checks.py`, `cross_check.*`, `tmtf_ref.py`, `app_check*.js`, `verify_result.py`, `lean/`) |
